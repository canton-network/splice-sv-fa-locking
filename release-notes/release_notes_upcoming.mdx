## Upcoming for next patch release:

{/* Add all release notes in this section */}

  - Scan App

    - `/v0/events` responses now include two new per-event fields:

      - `asset_activity_records`: asset-side activity records (CIP-104). Omitted from JSON when there is no asset activity.
      - `submitting_app_provider`: the submitting app provider party identifier when the submitter is a featured-app. Omitted from JSON when absent.

    - CIP-104 v1.1 populates four optional fields on `OpenMiningRoundSummary`:
      `optIssuancePerFeaturedAppRewardCoupon`, `optUnclaimedAppRewards`,
      `optIssuancePerFeaturedAssetRewardCoupon`, and
      `optTotalFeaturedAssetRewardCoupons`. The two `*Asset*` fields carry
      the asset-side issuance ratio and the total featured-asset reward
      coupons.

    - Explorer operators:

      Because featured-app and featured-asset activity now have separate
      issuance ratios, explorers should ingest the new `*Asset*` fields
      alongside the existing app-activity ones; explorers that only read the
      app-activity fields will under-report total app rewards minted.

    - changed `/v0/internal/reward-accounting-process/rounds/{round_number}/activity-totals` to include additional fields

  - SV App

    - Support changing the `governanceLockManagementConfig` fields in `DsoRules` config vote requests.

  - Governance locks

    - The `cip-127/*` metadata entries (e.g. `cip-127/lock-kind` and `cip-127/lock-status`), which were created by accident in the metadta, are no longer
      written to the metadata of governance lock transfer instructions and of lock transfer and substitution proposals.
      Read the lock information from the `cip-127/memo:` memo in the reason
      (`splice.lfdecentralizedtrust.org/reason`) instead.

    - Daml Model Changes:

      - Add underlock enforcement for featured app rights, as specified in
        [CIP-127](https://github.com/canton-foundation/cips/blob/main/cip-0127/cip-0127.md).
        A featured app provider that does not keep enough Amulet locked loses its featured status:

        - Add the optional `underlockPermanentAt` field to `FeaturedAppRight`. If it is set, the featured app right is suspended:
          `FeaturedAppRight_CreateActivityMarker` creates no activity markers,
          and transfers do not record the provider as a featured app provider.

        - Add the `SRARC_CreateFeaturedAppUnderlockInstruction` vote action. It creates a `FeaturedAppUnderlockInstruction`
          that records that SVs observed a provider to be underlocked, or to have recovered from an underlock.
          SVs execute it with `DsoRules_ExecuteFeaturedAppUnderlockInstruction`, which sets
          `underlockPermanentAt` to the end of the grace period, or clears it after a recovery.

        - Add `DsoRules_EnforceFeaturedAppPermanentUnderlock`, which archives a suspended featured app right
          after its `underlockPermanentAt` deadline passes.

        - Add the `SRARC_CreateRevokeFeaturedAppRightInstruction` vote action. It creates a `RevokeFeaturedAppRightInstruction`,
          which SVs execute with `DsoRules_ExecuteRevokeFeaturedAppRightInstruction` to archive the featured app right of a provider.

            This is required to ensure that revocation votes do not refer to the featured app right by its contract-id, which risks
            the votes becoming stale as the right may be mutated, which results in a new contract-id. The existing
            `SRARC_RevokeFeaturedAppRight` action is susceptible to this risk, and is therefore deprecated.

        - Both instruction templates expire after the vote request timeout.
          SVs archive expired instructions with `DsoRules_ExpireFeaturedAppUnderlockInstruction`
          and `DsoRules_ExpireRevokeFeaturedAppRightInstruction`.

      - Add the optional `governanceLockManagementConfig` field to `DsoRulesConfig` with these fields:

        - `featuredAppUnderlockEnforcementEnabled` (default true)
        - `featuredAppBasicLockThreshold` (default 5M CC)
        - `featuredAppAssetMovingLockThreshold` (default 5M CC)
        - `featuredAppAssetLockThreshold` (default 25M CC)
        - `featuredAppUnderlockGracePeriod` (default 7 days)
